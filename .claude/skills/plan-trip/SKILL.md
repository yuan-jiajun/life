# plan-trip · 旅行攻略整理

把"互联网上一堆攻略"变成"一份能照着走的计划"。核心不是搬运景点列表，而是**形成观点**——分级、避坑、路线取舍、节奏检验——然后决定这趟旅行**最合理的输出形态**，写进 `destinations/<地区>/<子区>/`（如 `新疆/北疆/`）。

这是一个方法论工具，不是模板填空。结构由这趟旅行决定（见 [阶段四](#阶段四成稿因地制宜)）。路径都相对仓库根目录。

## 这个 skill 解决什么

普通做法的毛病：搜出来的全是旅行社软文和"打卡20个景点"的流水账，看完还是不知道**该砍什么、哪里该多待、哪天会踩坑**。本 skill 的产出标准是一句话：

> 看完计划就知道**节奏对不对、哪些能删、哪天有硬约束**——而不是"景点真多"。

参照样板：`destinations/新疆/北疆/攻略.md`（景点分级 + 避坑 + 路线方案对比）和 `destinations/新疆/北疆/行程.md`（每天带里程/车程、早起错峰点、缓冲日）。这是质量下限。

## 工作流（五个阶段）

### 阶段一 · 立意（先问清，再动手）

后面所有取舍都由这几个变量决定，缺了就问用户，别瞎猜：

- **目的地 + 季节/具体月份**（同一地点不同月份体验天差地别）
- **天数 + 出发地**（决定能塞多少、路上耗多少）
- **同行人**（亲子/朋友/老人——影响体力和节奏）
- **风格**（自然风光 / 人文历史 / 摄影 / 躺平度假）
- **硬约束**（预算、是否自驾、体力、必去/必避）

### 阶段二 · 采集（这是 harness，下面是跑通过的真实配方）

用 `WebSearch` 拉面，用 `WebFetch` 钻深。**实测有效的查询矩阵**——每类都搜一次：

```
WebSearch: "<目的地> <月份> 自驾/玩法 攻略 避坑 行程"
WebSearch: "<目的地> <天数>天 路线 真实游记 注意事项"
WebSearch: "<目的地> 劝退 / 不值得 / 踩坑"        ← 专挑反向口碑，过滤软文
WebSearch: "<目的地> <景点> 预约 限流 门票 <年份>"  ← 时效性强，必带年份
WebSearch: "<目的地> 租车 / 包车 / 加油 / 路况"      ← 自驾线必查
```

**WebFetch 深挖**：对 `WebSearch` 给出的链接，挑可抓的源做深读，提取"建议停留时长、反常识要点、预约实操"。Prompt 要具体，例如：

```
提取<目的地>的具体避坑经验、每日节奏、各景点建议停留时长、门票与预约实操。只要最具体、最反常识的要点。
```

采集时**记账两件事**：①共识（多篇都说的）②矛盾（A 说必去 B 说劝退）。矛盾不要抹平，留到成稿里两面呈现 + 给替代方案。

**采集结果落地到情报日志**：每个目的地维护一份 `destinations/<地区>/<子区>/网络情报.md`，新采集**按日期分节往下追加**（带来源链接、标注 403/仅摘要的源），不覆盖旧节，也不直接动 `攻略.md`/`行程.md`。它是可随时读写的原始情报池；提炼/微调建议先写在这里，确认后再回灌到正式文件。

### 阶段三 · 提炼（把素材变成观点）

这是 skill 的高维度所在。至少产出这四样：

1. **景点分级**：🟢必去 / 🟡可去但控时 / 🔴可删。每项标"风景强度 / 折腾程度 / 值得停留天数"，删的理由要写。
2. **避坑清单**：**反常识的排前面**（例："禾木出村要坐 32km 区间车约 1 小时""赛湖出门 60km 才有加油站"）。这些才是攻略的真正价值。
3. **路线取舍**：给 2 个以上方案对比（全覆盖 vs 现实优化），说清各自代价，推荐一个。
4. **节奏检验**：用一句话判定行程是否合理——**有没有连续 2 天"不赶路、只玩一个地方"**。塞太满就砍。

### 阶段四 · 成稿（因地制宜，不套模板）

**先决定结构，再写。** 结构服从旅行类型，不是反过来：

- **自驾长线**（如北疆）：值得拆成多份——攻略（观点）/ 行程（逐日 + 里程车程）/ 花费 / 打包清单。可参考 `templates/`，但**可增删**。
- **城市短途 / 周末**：一篇足矣，别为凑结构硬拆。
- **多人协作或预算敏感**：花费单独成页；否则并进行程。

**回灌/更新已有计划时：默认不改路线和天数。** 多数新情报是"把已有计划做扎实"，不是推倒重来——先过节奏检验，确认确有硬理由（封路、季节错位、限流变化）才动结构，否则只把硬约束绑到对应那天。攻略只补缺口、不重复已有内容。

写 `行程.md` 时，每天落实：里程/车程预估、早起错峰点、留缓冲/机动日（让超时能顺延）。把素材里的硬约束**绑定到具体某一天**（见阶段五）。

**每日行程用表格呈现（统一规则）**：逐日行程默认排成一张总表，一眼可扫，不要每天一个小标题 + 散点列表。固定列：`Day | 日期 | 路线 | 里程/车程 | 当日重点 | 住宿`（自驾线必带"里程/车程"列；非自驾可换成"交通"）。

- **「当日重点」列内纵向分点**：用 `• 第一点<br>• 第二点<br>• …`，每个行动/景点一行，别挤成一长句。顺序即当天动线。
- **硬约束就地加粗**：加油、顺时针、抢票、留足时间等关键提示，在对应那一点里用 `**…**` 标出，不要丢。
- **里程/车程**列沿用下方标注口径；非赶路日写"慢游一整天/半天以内"。
- 表格放不下的长说明（路线总览图、全程里程小结、备注/缓冲日策略）留在表外，分别用段落或小节承接。

**里程/车程标注口径（统一规则，别乱拍脑袋）**：

- **里程**取地图导航（高德/百度类）两点间公里数；**多段路就分段写再相加**（例"特克斯→库尔德宁 120km/2h + →新源 100km/2h"），别只给一个总数。
- **车程取导航的纯驾驶时间，按路型逐段估**——高速段快、山路段慢、市内最慢，不要用"距离÷固定时速"套，那会把山路严重低估。当天多段相加写成"累计约 X h"。
- **明确声明不含游玩**：导航值不含下车拍照、堵牛羊、排队区间车，系统性偏低。赶路重的日子提示"实际会更久"，或叠一个游玩缓冲。
- **非赶路日不标时速**：环湖/草原慢玩/机动日只写"慢游一整天""半天以内"。
- **结尾给全程小结**：总里程（注明含不含市内）、日均区间、点名哪几天是长途日（如 7h）。

### 阶段五 · 校验（硬约束落地）

成稿后逐条核对，这些是"会毁掉一天"的东西，必须落到对应日期：

- **限流/预约**：哪天要 0 点抢票？哪个景区要提前传行驶证？（带年份重新确认）
- **封路/通车期**：独库类公路的通车月份、雨雪临时封路的缓冲。
- **加油/补给**：长无人区前哪天必须加满油。
- **时效声明**：票价/预约规则每年变，成稿注明"以官方公众号当日为准"。

## Gotchas（实战踩到的，不是想当然）

- **知乎 / 小红书 / 微信公众号 `WebFetch` 常 403**。**首选解法：套 `r.jina.ai` 阅读代理**——`WebFetch https://r.jina.ai/<原始URL>`，它抓正文转 markdown，实测能拿下知乎全文（普通 `WebFetch` 对同一链接 403）。代理也失败再退回 `WebSearch` 摘要，或改抓携程游记(gs.ctrip.com)、腾讯新闻、CSDN、汽车之家——这些直接能抓。（注：`web.archive.org` 在本环境被屏蔽，别用。）
- **`WebSearch` 默认喂软文**：结果一堆旅行社"线路产品"和打卡流水账。靠"避坑 / 劝退 / 真实游记"这类词把反向口碑捞上来，信息密度高得多。
- **攻略时效性是头号陷阱**：预约规则、限流、票价**每年都变**。搜索必带年份（"2026 预约"），成稿写明以官方当日为准，别把三年前的票价当真。
- **季节决定一切**：禾木夏天鸡肋、冬天主场；薰衣草 6 月底最盛。漏掉月份攻略直接跑偏，搜索词永远带月份。
- **矛盾别抹平**：那拉提这种"争议大"的点，呈现两方观点 + 给替代（夏塔/喀拉峻），比武断二选一有用。

## Troubleshooting

- **`WebFetch` 返回 403 Forbidden** → 目标站封抓取（知乎/小红书/公众号最常见）。先试 `WebFetch https://r.jina.ai/<原始URL>` 走阅读代理（实测能拿知乎全文）；不行再换可抓源（携程/腾讯新闻/CSDN）或用 `WebSearch` 摘要。`web.archive.org` 本环境屏蔽，不可用。
- **`WebFetch` 返回跨域 redirect** → 工具会把重定向 URL 交还给你，用新 URL 再调一次。
- **搜出来全是广告/旅行社线路** → 查询词加"避坑/劝退/真实游记/自由行"，并用 `blocked_domains` 屏掉纯营销站。
- **信息互相打架** → 正常。按"几篇都说"取共识，孤例存疑，矛盾点在成稿里两面写。
